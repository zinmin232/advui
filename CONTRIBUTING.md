# Contributing

Thanks for helping! This guide covers the local setup, the workflow and what a
pull request needs.

## Setup

- Node 22+ and pnpm 12 (`npm install -g pnpm@12`; see the README's
  troubleshooting note about Corepack)
- For native work: Android Studio with an emulator, or Expo Go on a phone. iOS
  needs macOS with Xcode.

```bash
pnpm install
pnpm dev          # docs at http://localhost:3000
pnpm dev:expo     # Expo dev server
```

## Workflow

1. **Branch** from `main`: `feat/select-groups`, `fix/tooltip-escape`,
   `docs/theming`.
2. **Make the change.** For components, follow
   [COMPONENT_GUIDELINES.md](COMPONENT_GUIDELINES.md). New components start
   with `pnpm create-component <slug>`.
3. **Check it:**

   ```bash
   pnpm lint && pnpm typecheck && pnpm test
   pnpm test:native                 # when touching components or .native files
   pnpm test:e2e                    # when touching the docs or visuals
   ```

4. **Look at it** in the docs (light and dark, narrow and wide) and in Expo on
   at least one platform. If you could not run a platform, say so in the PR.
5. **Update visual baselines** when the look changes on purpose:
   `pnpm --filter @adv-ui/docs test:visual:update`. Review the new images
   before committing them.
6. **Add a CHANGELOG entry** under _Unreleased_.

## Commits and pull requests

- Use [Conventional Commits](https://www.conventionalcommits.org):
  `feat(select): support option groups`, `fix(toast): render above screens on Android`.
- Keep PRs focused, with one component or concern each.
- The PR description says what changed and why, how it was tested, and which
  platforms were checked. Include screenshots for visual changes.

## Code style

- Prettier (`pnpm format`) and ESLint are the source of truth.
- TypeScript is strict. No `any` in public APIs; prefer `unknown` plus
  narrowing.
- Tokens only in library code. The lint config rejects color literals.
- Comments explain **why**, not what: platform quirks, accessibility decisions,
  non-obvious constraints.

## Generated files

Don't edit these by hand. Change the source and re-run the generator:

| File(s)                                        | Generated by                                       |
| ---------------------------------------------- | -------------------------------------------------- |
| `packages/ui/src/meta/index.ts`, `examples.ts` | `pnpm catalog` (runs before `dev`/`build`)         |
| `registry/*.json`, `apps/docs/public/r/*`      | `pnpm registry:build` (runs before the docs build) |
| `packages/icons/src/generated.ts`, `icons.ts`  | `pnpm --filter @adv-ui/icons generate`             |

## Releases

Packages are versioned together.

1. Move the _Unreleased_ entries to a version section in `CHANGELOG.md`.
2. Bump `version` in the published packages (`core`, `theme`, `icons`, `utils`,
   `cli`) and in `apps/docs/src/lib/site.ts`.
3. `pnpm build`, then publish with `pnpm -r publish --access public`.
   `publishConfig` points the entry points at `dist/`.

## Reporting issues

Include the component, platform (web browser, iOS or Android version, Expo Go
or dev build), a minimal reproduction and what you expected. For accessibility
issues, name the assistive technology.
